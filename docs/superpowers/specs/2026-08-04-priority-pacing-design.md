# 取得優先順位×時期に応じた出題ペーシング 設計書（2026-08-04）

## 背景・目的

CEOフィードバック（2026-08-04）:
- 絶対に落とせない宅建業法・権利関係が「今日の問題」の主軸に選ばれるべき。
- 法令上の制限などの暗記科目は直前に詰め込みが効くので、時期に合わせて出題されるべき。
- ペーシング（いつ何をやるか）はAIの役割。

現状の自動出題（今日やる）は「復習期限 → 未回答」の順で、未回答は固定の科目順
（宅建業法→権利関係→法令上の制限→税・価格評定→免除科目）を**直列**に消化する。
問題点は2つ:

1. 宅建業法100問を解き切るまで権利関係が1問も出ない（主軸2科目の並行学習にならない）。
2. 試験日との距離に関係なく、業法・権利が終わり次第すぐ法令・税・免除に進む
   （早く着手しすぎると本番までに忘れる。暗記科目は記憶の鮮度が価値）。

## セオリー上の根拠（出典）

- 序盤は権利関係・宅建業法から着手し、法令上の制限・税は後回しにする:
  伊藤塾「宅建の勉強スケジュールの組み方」
  https://column.itojuku.co.jp/takken/method/benkyou-sukejuuru/
  （3ヶ月スケジュールは権利関係・宅建業法から開始。6ヶ月案でも法令・税は序盤「まだ手をつけなくてもいい」）
- 税その他は深追いしない（捨て問戦略）: 伊藤塾「勉強する順番」
  https://column.itojuku.co.jp/takken/method/benkyou-junban/ （既存出典）
- 直前期の定義: アガルート「直前対策」 https://www.agaroot.jp/takken/column/chokuzen/
  （直前期＝概ね試験前2.5ヶ月。この期間は過去問演習・弱点補強中心）

※「暗記科目の解禁を試験何日前にすべきか」の具体日数を明示する出典は確認できなかったため、
解禁日はアプリ自身の消化工数から逆算して決める（下記）。推測値を出典付きの事実として書かない。

## 設計

### フェーズ（2段階）

試験日までの残日数 `daysToExam` で切り替える。

| フェーズ | 条件 | 新規問題の科目重み |
|---------|------|------------------|
| 基礎固め期 | daysToExam > 45 | 業法3 : 権利2 :（法令・税・免除は0＝後回し） |
| 直前期 | daysToExam ≤ 45 | 業法4 : 権利3 : 法令3 : 税1 : 免除2 |

- **45日の根拠（逆算・オンペース前提）**: 暗記3科目の初回消化は80問
  （法令40・税15・免除25）。ペーシングどおり進んでいれば直前期の時点で
  業法・権利の新規は消化済みなので、新規枠（1日5〜7問）の全量が暗記科目に回り、
  初回一巡は約12〜16日。習得（3連続正解）には間隔反復の+2日・+7日が乗り、
  最終14日は復習予備（既存 `reviewReserveDays = 14`）。
  最終問の習得完了 ≈ 試験45−16−9 = 20日前 > 予備14日前で、余裕を持って収まる。
  ※着手が遅れて業法・権利の新規が残っている場合はこの計算は成立せず、
  下記の混合重みで「主軸優先のまま暗記も並行」に縮退する（破綻ではなく減速）。
- **基礎固め期の3:2**: 出題数比（業法20問:権利14問/回 ≒ 3:2）と目標配点
  （18点:10点）の双方に整合する。
- **直前期に業法4:権利3を残す理由**: 順調に進んでいれば業法・権利の新規は
  直前期には残っておらず、実効的に法令3:税1:免除2の詰め込みになる。
  着手が遅かった場合は業法+権利で新規枠の7/13（約54%）を保ち、
  最重要科目が暗記科目に埋もれない（codexレビュー指摘を反映して3:2→4:3に増量）。
- **重み0の科目**: 除外せず**最後尾**に回す。主軸2科目を解き切った場合に
  出題が止まらないためのフォールバック（既存の「復習+未回答が尽きたら終了」挙動は不変）。

### 選定アルゴリズム（決定的・入力ゼロ）

未回答問題を科目ごとに既存の安定順（年度新しい順→問番号）で並べ、
**重み付きラウンドロビン**で1本の順序に混ぜる:

- 各問題のキー = （科目内での順番+1）÷ 科目の重み。キー昇順に出題。
- 重み0はキー∞扱いで最後尾（科目順は既存 `studyOrder` に従う）。
- 同キーは `studyOrder` の順で安定タイブレーク。
- 例（基礎固め期）: 業法, 権利, 業法, 業法, 権利, 業法, 権利, …（5問単位で3:2）

復習（期限到来）問題の優先は現状維持（ペーシングより常に先。間隔反復のエンジンは触らない）。
追加入力はゼロ。試験日は既存設定（既定 2026-10-18）をそのまま使う。

### 実装配置

- `src/data/studyGuide.ts` — フェーズ定義（閾値45日・重み表・根拠コメント・出典）を追加。
  科目データの単一情報源をここに保つ（既存方針の踏襲）。
- `src/lib/pacing.ts`（新規） — 純関数
  `sortByPacing(questions, daysToExam)`：未回答問題列を重み付きラウンドロビン順に並べ替える。
  `phaseForDaysToExam(daysToExam)`：フェーズ判定（UI表示にも使う）。
- `src/lib/pacing.test.ts`（新規） — vitest。フェーズ切替・3:2交互・重み0の最後尾・
  直前期の実効法令詰め込み・残日数負値（試験当日/超過）の各ケース。
- `src/App.tsx` — 変更は3点のみ:
  1. `startMission` の「最初の未回答」選定を `sortByPacing` 経由にする。
  2. `goNext`（studyMode）の「次の未回答」選定を `sortByPacing` 経由にする。
  3. 「今日やる」カードに現在フェーズの1行表示
     （例:「いまは宅建業法・権利関係を固める時期」「直前期: 法令・税・免除を詰め込む時期」）。
     ペーシングが黙って動くと故障に見えるため、挙動を1行で説明する。
- 一覧（問題を選ぶ）・年度/分野の個別演習・模試・復習キューの並びは**変更しない**。

### エッジケース

- daysToExam が負（試験日超過）: 直前期扱い。
- ユーザーが分野フィルタを手動指定した場合: フィルタ後の集合内でペーシング順を適用
  （ユーザーの明示選択が優先。ペーシングは順序のみ関与）。
- 業法・権利をすべて習得済みで基礎固め期が続く場合: フォールバックで法令以降が出る（停止しない）。

## 採用しなかった代替案

- **案B: 科目の時限ロック（解禁日まで法令を完全に出さない）** — 単純だが、主軸を
  解き切った時に出題が止まる。フォールバック付き重み方式の方が安全。
- **案C: 目標点ギャップ×残日数の動的緊急度スコア** — 適応的だが挙動が説明不能になり、
  「なぜこの問題が出たか」をCEOに1行で説明できない。過剰設計と判断。
- **案D: 全期間固定重み（フェーズなし・codex提案）** — フェーズ切替の崖は消えるが、
  「暗記科目は直前に詰めて記憶の鮮度を保つ」というCEOの明示要望（2026-08-04）と
  正面から矛盾するため不採用。切替の崖は「詰め込み開始」の意図された挙動と位置づける。
- **codexレビューのうち棄却した指摘**: 復習優先の見直し（既存の間隔反復エンジンは
  本件のスコープ外・CEOの要望は新規問題の配分）、残作業シミュレーション4ケースの追加
  （個人用ドリルに対して過剰）、免除科目の対象/非対象分岐（既存設計のまま）。

## デメリット（自己申告）

- 閾値45日・重み比は逆算による設計値であり、出典に直接の数値根拠はない（上記のとおり明記）。
  CEOの体感と合わなければ `studyGuide.ts` の定数1箇所の変更で調整できる。
- 直前期に一気に法令が流れ込むため、その週の体感難度が上がる（暗記科目ゆえ許容と判断）。
