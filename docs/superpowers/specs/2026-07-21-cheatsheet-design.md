# 自分専用チートシート — 設計書

作成日: 2026-07-21

## 目的

試験当日に見ることを想定した、学習者本人専用の優先論点一覧。
「自分が落としやすく（弱点）」「本試験でよく問われ（出題頻度）」「得点効率が高い（配点重み）」
論点を優先度順に並べ、上から潰せば当日の1点を最大化できる状態にする。

## スコープの前提（決定事項）

- **自分専用**。対象は自分の進捗ひとつだけ。
- **アプリ内で自動計算**して表示する。外部AI生成・Firestore追加・Cloud Functions・
  APIキーは一切使わない。弱点データはアプリが既に持つ `answers`、出題頻度は過去問由来の
  静的データなので、その場で計算できる。
- 既存の「AIコーチのアドバイスページ」（別設計 `2026-07-21-ai-coach-page-design.md`）とは
  独立した機能。混ぜない。

## 2軸＋配点重み（優先度スコアの根拠）

学習科学のベストプラクティス（パレートの法則＝頻出20%が結果の80%を生む／苦手の早期克服／
宅建特有の科目別配点戦略）をリサーチで確認した上で、次の3要素で優先度を出す。

- **弱点度** — その論点の問題群での不正解回数 `lapses` と正答率から算出。未着手も弱点として扱う。
- **出題頻度** — 過去問データで、その論点が何問出題されたか（静的に事前集計）。
- **配点重み** — `studyGuide.ts` の科目別 `targetScore/fullMarks`（得点効率）を係数として掛ける。
  これにより「宅建業法（満点狙い）」の論点が上位に、「税その他（捨て問）」の低頻度論点が
  下位に来る、という宅建の得点構造に忠実な並びになる。

```
優先度スコア = 弱点度 × 出題頻度 × 配点重み
```

参考にした出典（2026-07 時点）:
- 頻出論点優先（出題ヒートマップ論）: https://takkenai.hatenablog.com/entry/exam-heatmap-priority-study
- 苦手の早期克服・分野別傾向: https://studying.jp/takken/about-more/takken-howtostudy.html
- パレートの法則と直前期の高頻度優先: https://blog.learnhall.com/2025/08/29/the-science-of-spaced-repetition-how-to-retain-more-in-less-time/

## スコアリングの透明性（ユーザーにも分かる形にする — 必須要件）

優先度スコアは「なぜこの論点が上位なのか」がユーザーに見える形で提示する。ブラックボックスに
しない。具体的には各行で次を満たす:

- **3つの構成要素を素の数値で見せる**: 「あなたの正答率 ○%（ミス ○回）」「過去 ○問 出題」
  「科目の重み（例: 宅建業法＝満点狙い）」を各行に併記する。
- **優先度は生スコアの桁ではなく、意味の分かる指標で見せる**: 相対的な順位（1位〜）と、
  「なぜ上位か」を一言で示すラベル（例: 「頻出なのに苦手」「捨て問だが未着手」）を添える。
- **計算式を明示する説明ブロックをページに置く**: 「優先度＝あなたの弱点 × 出題の多さ ×
  科目の得点効率 で並べています」という一文と、3要素それぞれの意味を書く。
- スコアの正規化方法（弱点度・頻度をどう0〜1などに揃えるか）は実装で決めるが、
  **表示は生の数値（正答率%・ミス回数・出題問数）を主役にし、合成スコアは順位付けの裏方に留める**。
  ユーザーが自分の目で「確かにここは苦手で、よく出るな」と納得できることを最優先する。

## アーキテクチャ（アプリ内で完結・4ユニット）

### 1. 論点タグデータ `src/data/topicTags.ts`（新規・Claude が作成）

- 型:
  ```ts
  export type Topic = { id: string; label: string; category: string };
  export const topics: Topic[];                       // 論点マスタ
  export const questionTopics: Record<string, string>; // questionId -> topic.id
  ```
- 各過去問を科目より細かい論点（例: 抵当権、35条書面、都市計画法…）に分類する。
- **原本 `questions.ts` は改変しない**。別ファイルで questionId 参照により紐付ける
  （原本主義メモリ [[takken-drill-original-text-policy]] に準拠）。
- 粒度は標準的な宅建の論点区分に合わせ、各科目おおむね10〜20論点程度。
- タグ付けは Claude が全問に対して行う。

### 2. 優先度算出ロジック `src/lib/cheatsheet.ts`（新規）

- 入力: `answers`（進捗）、`questionTopics` / `topics`、`studyOrder`。
- 出力: `CheatSheetRow[]` を優先度降順で返す純粋関数。
  ```ts
  export type CheatSheetRow = {
    topicId: string;
    label: string;
    category: string;
    rank: number;             // 1始まりの優先順位
    priorityScore: number;    // 合成スコア（裏方・並べ替え用）
    // ↓ ユーザーに見せる素の数値
    accuracy: number;         // 自分の正答率 0〜1（未着手は null 相当の扱い）
    lapses: number;           // 自分のミス回数
    attempts: number;         // 自分の挑戦回数
    questionCount: number;    // その論点の過去問出題数
    categoryWeight: number;   // 科目の得点効率（targetScore/fullMarks）
    reasonLabel: string;      // 「頻出なのに苦手」等の一言理由
    untouched: boolean;       // 未着手フラグ
  };
  ```
- 副作用なし・決定的。テスト可能。

### 3. 表示 `src/App.tsx` に「チートシート」ページ

- 既存の導線（今日やる／ほかの学習／成績を見る等）と並ぶ入口を1つ追加。
- 構成:
  - 冒頭にスコアリングの説明ブロック（計算式と3要素の意味）。
  - 優先度順リスト。各行: 順位・論点名・科目バッジ・一言理由ラベル・
    「あなた: 正答率○%／ミス○回」・「過去○問 出題」・科目の重み表示。
  - 上位を強調。未着手論点は色分け。
- 未ログイン／進捗ゼロ時: 「まだ十分な学習データがありません」の空状態を出す。

### 4. テスト `src/lib/cheatsheet.test.ts`（新規）

- 弱点がない論点は下位に来る。
- 頻出かつ苦手な論点が上位に来る。
- 配点重みが効く（同条件なら業法 > 税）。
- 未着手論点が弱点として扱われる。
- reasonLabel が条件どおり付く。

## 役割分担
