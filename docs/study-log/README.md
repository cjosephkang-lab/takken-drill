# 学習ログ（study-log）

宅建アプリで解いた実績と、その日に書いたメモを、日付ごとに書き出したものを置く場所。

## 何のためのフォルダか

このフォルダは「発信パイプライン」の入り口。あとで Claude Code が git のコミット履歴と
合わせて読み、X 用・Note 用の発信素材を作る（skill `study-log-broadcast`）。

合格後にまとめて振り返ろうとしても、記録がなければ書けない。だから発信するかどうかとは
無関係に、毎日ためておく。

## 毎日やること

**何もしなくてよい。** アプリで解いてメモを書けば、それがそのまま溜まる。

毎朝7時に launchd が `scripts/daily-coach.sh` を呼び、その中で
`scripts/study-log.py` が**前日ぶん**を書き出す（朝7時の時点で当日はまだ
解いていないので、今日ではなく昨日を書く）。

## 手で叩く

```bash
python3 scripts/study-log.py                  # 今日ぶん
python3 scripts/study-log.py --date 2026-09-08
python3 scripts/study-log.py --backfill       # 記録のある全日ぶん（既存ファイルは上書きしない）
python3 scripts/study-log.py --stdout         # ファイルに書かず標準出力だけ
```

`gcloud auth login` が済んでいることが前提。

## 数字とメモの出どころ

| 中身 | 出どころ |
|---|---|
| 解いた問題数・正解数 | Firestore `progress/{uid}` の `dailyLog[日付]` |
| 科目の内訳 | 同 `answers[].answeredAt` を日本時間の日付で数える |
| メモ本文 | 同 `notes[].text` |
| メモをどの日に置くか | 同 `notes[].updatedAt` を日本時間に直した日付 |
| 年度・問番号・科目 | `src/data/questions.ts` |

## 読むときの注意

**メモは上書き保存**なので、同じ問題のメモを後日書き直すと、古い日付のログから
そのメモが消え、書き直した日のログに移る。「その日に書いた文面」の履歴ではなく、
「その日に最後に触ったメモの現在の中身」が出る。

**科目の内訳は dailyLog の解答数より少なく出ることがある。** `answers` は問題ごとに
最新の1件しか持たないため、同じ問題を1日に何度も解いた分は数えられない。
実績の行（解いた問題数）が正で、内訳は目安。

## 以前のやり方（2026-09-09 廃止）

かつてはアプリの「今日の学習を書き出す」ボタンを押し、コピーされた内容を自分宛に
Gmailで送り、それを Claude Code が検索して保存していた。実績もメモもすべて
Firestore に入っており、この手渡しは最初から不要だった。手作業が要る設計だったため
2026-07-27 の1件で止まり、以降6週間ぶんが溜まらなかった（`--backfill` で復元済み）。

アプリの書き出しボタン自体は残してあるが、このフォルダのためには押さなくてよい。
