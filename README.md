# 宅建過去問ドリル

直近5回分の宅地建物取引士資格試験の公式過去問を使う、スマホ向けの個人用ドリルです。

## 根拠データ

問題・正解番号は、一般財団法人 不動産適正取引推進機構が公開している「宅建試験の問題及び正解番号表」から取得しています。

- 令和7年度
- 令和6年度
- 令和5年度
- 令和4年度
- 令和3年度12月試験

令和4年度・令和3年度12月試験は公式PDFがスキャン画像のため、OCR結果から問題文を復元しています（`src/data/restoredQuestions.json`）。まずOCRに残った日本語の文字化けを直し（原本にない文章は推測で補いません）、OCRで完全に失われた箇所は、各問の解説リンク先である宅建レトスの掲載問題文（公式の問題文の写し）から該当箇所だけを補いました。補った文言は、宅建レトスと公式PDFに照らして確認しています。この結果、250問すべてに問題文がそろっています。各問題カードから公式PDFを開いて原本確認できます。

`src/lib/unreadableChoices.ts` は、正解の選択肢が判読できない問を検出して問題カードと模試に警告を出す仕組みです。現在は該当0問ですが、将来データが欠けたときの安全網として残しています。

復元・補完したテキストは、生成のたびに作り直せないため（`build/` と `source-pdfs/` はリポジトリに含めていません）、`src/data/restoredQuestions.json` としてコミットしています。`npm run data` はこのファイルを読んで `src/data/questions.ts` を組み立てます。

## 解答解説

各問題には、公式PDFの正解番号表に基づく「公式の答え」を表示します。詳しい解説は、公開されている宅建レトスの該当ページへ「解答解説を見る」としてリンクします。第三者の解説本文は転載せず、出典ページを直接開く設計です。

## 学習導線と成績ボード

効率よく一発合格するための定番セオリーをアプリに組み込んでいます。最初に設定を選ばせず、トップの「今日やる」から始める設計です。

- **今日やる**：試験日から逆算した今日の問題数を出し、復習する問題 → まだ解いていない問題の順で自動出題します。まだ解いていない問題は、試験日までの残り日数に応じた科目配分で選びます（基礎固め期＝残り46日以上は宅建業法・権利関係を3:2の主軸に、直前期＝残り45日以内は暗記中心の法令・税・免除科目を詰め込む配分。根拠と出典は `src/data/studyGuide.ts` と `docs/superpowers/specs/2026-08-04-priority-pacing-design.md`）。
- **ほかの学習**：復習、模試、年度・分野の3つに絞っています。普段は「今日やる」だけで進められます。
- **成績を見る**：科目別の正答率を本番1回（50問）に置き換えた「予想点」を表示し、目標点まであと何点かを可視化します。

学習導線の科目順・目標配点・合格ラインは、以下の予備校／専門サイトを横断して一貫して支持されている定番セオリーに基づいています（解説本文は転載せず、各社の代表値を採用）。

- 伊藤塾「宅建の合格点」 https://column.itojuku.co.jp/takken/basic/goukakuten/ （合格点：過去10年で最低33点〜最高38点・平均35.5点）
- 伊藤塾「勉強する順番」 https://column.itojuku.co.jp/takken/method/benkyou-junban/
- アガルート「科目構成」 https://www.agaroot.jp/takken/column/composition/
- 全日埼玉「勉強の順番」 https://saitama.zennichi.or.jp/column/study-order/
- 四谷学院「科目別の目標点数」 https://yotsuyagakuin-tsushin.com/blog_takkenshiken/kamokutensuu/

科目順・目標点の具体値とその根拠コメントは `src/data/studyGuide.ts` に集約しています。

## 学習効率エンジン（間隔反復 × 想起練習）

一発合格に向けて、学習科学で定番の2手法をアプリに組み込んでいます。

- **間隔反復**：間違えた問題は翌日、正解を重ねるほど間隔を広げて（1回→2日、2回→7日、3回→14日、以降30日）「忘れかけた頃」にもう一度出題します。
- **想起練習（テスト形式の解き直し）**：一度解いた問題も、アプリを開き直すと前回の答えは表示されず、毎回「思い出して解く」形式になります。3回連続で正解すると「身についた問題」として扱います。
- **「次へ」の優先順位**：通常学習では復習期限の問題 → まだ解いていない問題の順に自動出題します。対象を終えたら既回答問題は循環せず、年度・分野を指定して個別に演習できます。

## 想起機会を増やす・「なぜ間違えたか」を捕まえる（2026-09-09追加）

設計の正: `docs/superpowers/specs/2026-09-09-ai-learning-features-design.md`。AIは問題データを一切書き換えず、公式ドリルの流れに法律解説を混ぜません。AIの出力は「推定」「照合結果」として別枠に出し、出典リンクを添えます。LLMはアプリからは呼ばず、朝のコーチと同じ経路（Mac上の `scripts/ai-insights.py` → Firestore `insights/{uid}`）で夜間に動かします。

- **肢別○×**（AI不要）：「正しいものはどれか」型なら正解肢＝真・他3肢＝偽、「誤っているものはどれか」型ならその逆、と公式の正解番号表だけから各肢の真偽を導き、1肢ずつ○×で答えます。1問が4回の想起練習になります（対象209問・836肢。「いくつあるか」「組合せ」「複数正解」は対象外。判定は `src/lib/choiceStatements.ts`、出題順は `src/lib/choiceQueue.ts`）。
- **自信があったのに間違えた問題を最優先で復習**（AI不要）：自信なし印なしの不正解は、誤った記憶で確信して外した問題なので、復習キューと「今日やる」の復習で先頭に出します。絞り込みにも追加。
- **誤答の原因（推定）**：選んだ肢・正解肢・回答秒数・自信印・メモから、夜間バッチが「知識欠落／数字混同／読み違い／論点混同／まぐれ」を推定し、問題カードの解説枠に「前回の誤答の原因（推定）」として出します。コーチ枠に集計と助言。単発の誤答では断定できないため「推定」と明示します。
- **混同ペアの比較**：誤答の履歴から取り違えている論点の組を推定し、「ほかの学習」の「比較」から2論点の問題を交互に解けます。終えると対象問題の次回復習を翌日に寄せ、通常の復習で他の論点に混ぜて再出題します（並べて比べた直後は見かけ上できるようになるだけなので）。
- **メモの照合**：各問にリンク済みの解説ページ本文を根拠に、メモとの食い違いを夜間に検査し、メモ欄の下に出典付きで出します（従来の数字照合 `scripts/note_facts.py` も併用）。メモを直すと「未照合」に戻ります。
- **説明できるかチェック**（任意）：2回以上間違えた問題だけ、回答後に「根拠を一言」欄を出します。夜間に解説ページと照合して「一致／根拠ずれ／数字ずれ」を返します。
- **法改正の注記**：古い年度で現行法と変わる箇所は、バッチが候補を `docs/law-changes/candidates.json` に出し、人が一次情報で確認したものだけ `src/data/lawChanges.ts` に書いて問題カードに注記します。AIの候補をそのまま表示しません。

回答イベント（問題ID・選んだ肢・正誤・自信印・回答ミリ秒・時刻）は `progress` に直近2000件まで保存し、端末間では時刻をキーに和集合を取ります。

## 学習体験（習慣化と本番対策）

- **今日やる**：復習する問題＋新しい問題から1日の目標問題数を自動で出し、「今日の◯問を始める」の1タップで最適な順（復習→まだ解いていない問題、合格者の鉄則順）に出題します。
- **試験日カウントダウンと逆算ペース**：試験日（既定は次回本試験日）を設定すると、「あと◯日・1日◯問で間に合う」を表示し、今日の目標数に使います。
- **ストリークと学習カレンダー**：連続学習日数と過去12週のヒートマップで継続を可視化。
- **模試モード**：本番同様の50問・2時間タイマー。途中の正解・不正解は非表示で、採点後に得点・科目別分析（目標点との比較）を表示し、結果は学習履歴に残ります。50問そろっている全5年度で受験可能です。

## 使いやすさ

- 成績を見る、年度・分野の選択は必要な時だけ開く設計です（開閉状態・各フィルタは保存され、次回起動時に復元）。
- 画面下に「前へ／次へ」の固定ナビ（iOSセーフエリア対応）。
- OCR由来で「ア〜エ」の記述の改行が失われた問題（28問）は、公式データを書き換えずに表示時に自動で段落分けして読みやすくしている（`src/lib/formatQuestionText.ts`。全250問に対して改行以外の文字が変化しないことを機械検証済み）。

## 端末間同期（任意）

ログインしない場合は、その端末のブラウザに回答履歴・自分メモを保存します。Googleで保存すると回答履歴・自分メモがFirestoreに保存され、他の端末（PC⇄スマホ）でも同じ状態を引き継げます。

- 同期は問題ごとに「最終回答日時が新しい方」を採用してマージします。
- 本人のデータは本人（ログイン中のGoogleアカウント）以外アクセスできません（`firestore.rules`）。
- ローカル開発でこの機能を使うには `.env` にFirebaseプロジェクトの設定値（`VITE_FIREBASE_*`）を用意してください。未設定の場合は同期UIごと非表示になります。

## UI/UX計測

Firebase Analyticsが有効な環境では、UI改善用に以下の指標を送信します。UID、メールアドレス、自分メモ本文、問題文、選択肢本文は送信しません。

- 起動、セッション時間、端末幅区分、同期状態
- 今日やる、復習、年度・分野フィルタ、成績ボード、外部リンクの利用
- 問題表示、回答、回答までの秒数、回答ボタン位置、復習対象かどうか
- 模試の開始、回答、採点表示、中断、完了、時間切れ
- 初回表示、読み込み時間、LCP/CLS/INP相当の性能指標
